## Why it matters

RAG collega il modello parametrico a una memoria esterna: recupera documenti e genera risposte fondate, aggiornabili e più verificabili.

### Note · page 2

> Dense Passage Retriever

Usano Dense Passage Retriever (DPR).

La query:

"Who discovered penicillin?"

viene trasformata in un embedding:

q(x)

Anche i passaggi di Wikipedia hanno embedding:

d(z_1),d(z_2),...,d(z_n)

e fanno essentially una similarity search:

q(x)^T d(z)

ottenendo i top-K passaggi più rilevanti.

Il documento è una variabile latente: non dici esplicitamente al sistema "questo è il documento corretto". Il sistema considera diversi documenti recuperati e pesa quanto ciascuno spiega bene la risposta.

### Note · page 3

> RAG-Sequence, the model uses the same document to predict each target token.

Assumono che un documento sia responsabile dell'intera risposta.

### Note · page 3

> RAG-Token, can predict each target token based on a different document

Qui fanno una cosa ancora più interessante.

Ogni token può essere supportato da documenti differenti:

token 1 ← documento A
token 2 ← documento A
token 3 ← documento B
token 4 ← documento C
...

### Note · page 3

> n the RAG-Token model we can draw a different latent document for each target token and marginalize accordingly.

nel RAG-Token originale NON rifanno una nuova ricerca con una query diversa a ogni token.

La differenza di RAG-Token è come vengono combinati.

Non scegliamo prima quale documento è quello giusto. Facciamo predire il prossimo token al modello usando ciascun documento, pesiamo ogni previsione in base a quanto il retriever ritiene rilevante quel documento e sommiamo tutto.

### Note · page 5

> We also note that some MSMARCO questions cannot be answered using Wikipedia alone. Here, RAG can rely on parametric knowledge to generate reasonable responses

Se Wikipedia contiene informazioni utili → RAG le recupera.

Se Wikipedia non le contiene → il generator può comunque sfruttare ciò che ha appreso durante il pre-training.

Quindi questo esperimento serve a dimostrare che RAG non è semplicemente:

“retrieval → copia la risposta”

ma:

“retrieval → usa le informazioni recuperate insieme alla conoscenza interna → genera liberamente una risposta.”

Ed è proprio il significato di Retrieval-Augmented Generation: il retrieval aumenta il modello generativo, non lo sostituisce.
